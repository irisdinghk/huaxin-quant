# 推进评分独立试算参考（research_v1）

## 预算与边界

配置 `02-quant-trial.json` 仅供研究脚本读取。生产 `02-quant.json`、`quant_filter.py` 及第一步推进识别不改。

基础项为原结构阶段分×40/55、原整理量能分×20/30、推进贡献最高30、原趋势分×5/15、原位置分×5/22。沿用各原项内部条件和扣分；基础和截断0—100后另加原扩展分（0—12），总分0—112。没有原组/没有正向推进时该项零，真实数据缺失则总分null并列已知分项。

## 推进质量与保留

Q为0—100：涨幅40、上涨日放量20、上涨/下跌日均量配合20、路径效率15、时间效率5。涨幅`(H/B-1)*100`；放量为上涨日均量/起点前20条均量；配合为上涨日均量/下跌日均量（使用两个相对基准倍数之比）。方向按收盘相对前日收盘；只计算`(B,H]`的量能。没有下跌日时配合不适用，以放量评分承担量能40，输出重分配标记，不制造无限比值。基准不足20、真实缺失量/价格或无效区间使评分不完整。

路径效率E为净推进/累计收盘绝对变动，直接取0—1；时间效率以交易记录间隔n计算日均复合推进速度`100*expm1(log(H/B)/n)`，不把收缩历时混入。

L取当前研究阶段`selected.retention.rounds`所有段`close_low`的最小值；原始R=`(L-B)/(H-B)`，评分R截断0—1。重建仅读取新阶段，不使用`post_peak`桥接路径、当前恢复或日内低点替代L。推进贡献=`30*Q/100*R`，不以12%涨幅标签或绝对回撤设新增资格门槛。保存原始负数或大于1的R及警示。

## 标定与冻结

- 只用指定标定日的全量主窗口研究对象。以股票代码、B/H日期去重；不筛选赢家、生命周期、财务或量能标签。价格与完整20日基准量有效才进入标定，保留原数据状态。
- 各指标采用有界线性映射：涨幅和速度从0起分，两个量能比从1起分；达到该指标标定样本90分位给满分，以上封顶。分位数以线性插值计算；每项至少20个有效样本且上界须高于起点，否则拒绝标定。保存数量、分位分布、去重样本、起止日期、映射及配置哈希。
- 9/15标定后冻结用于9/16。相邻日有重叠锚点，不能视作独立样本外验证；历史事件锚点套用9/15参数为敏感性研究，不声称参数当时可得。不按个股涨幅反馈修订映射。

## 买点传导与比较

档案评分比较直接使用原权威记录的分项与其原组研究证据，避免当前重识别改变比较对象。另在独立内存模块中只替换评分函数和买点评分换算，重放同输入生产算法；原算法、硬过滤、收缩识别、风险及动作规则均保持可用。当前与突破前/回踩对应的冻结锚点分别计算推进，禁止把分析日当前推进项灌入历史锚点。

试算主换算为结构总分/112×100，然后沿用原0.6权重和0—60封顶，动作与风险按原规则。并列原0.6直接乘再封顶的诊断（仅基础分差异，不声称另做了完整信号重放）。原买点数值门槛固定，等级/信号变化仅供接入前评估，不自动推荐交易。任一实际评分调用不完整时，完整重放结果标记不可用；内部兼容占位不冒充新规则输出。

分别保存原日权威、同输入原算法重算、档案分项试算及内存新评分重放；现有版本/行情差异单列。重放前后校验原生产算法输出哈希；原市场/策略库以只读连接打开，不运行daily或发布流程。

## 复现与产物

从运行实例执行：

```bash
.venv/bin/python scripts/audit_impulse_score.py --dates 260915,260916 --calibration-date 260915 --evidence-dir reports/research/impulse_evidence_v34_260915_260916_20261005 --output-dir reports/research/<新目录>
```

`calibration.json`冻结参数；`scores_*.json`保留完整明细、缺失及调用锚点；`comparison_*.csv`含分项和全量排序；`meta_*.json`含覆盖/状态/数据质量/等级和信号变化；`README.md`汇总结果与适用边界。原研究失败标的不补造记录，复权状态不提升。输出目录已存在时直接拒绝。
